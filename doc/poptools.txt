INTRODUCTION                                    *poptools-introduction*

Poptools aims to boost your productivity by using popups for a variety of
tasks—from finding files and directories to setting your favorite colorscheme.

Unlike similar plugins such as fzf, fuzzyy, or scope, Poptools
keeps things essential and runs external programs synchronously—which,
honestly, doesn’t bother me at all!

Configuration is extremely simple, and Poptools includes convenient features
like restoring your last search instantly or creating handy dashboards via the
`:PopupIndex` command.

And yes—you can search results both fuzzily or exactly.

COMMANDS                                          *poptools-commands*

It follows the list of available commands: >

    :PoptoolsFindFile
    :PoptoolsFindFileInPath # Takes into account the setting of :h 'path'.
    :PoptoolsFindDir # Search from the current directory downwards
    :PoptoolsBuffers # Note: <c-d> delete the highlighted buffer
    :PoptoolsRecentFiles
    :PoptoolsCmdHistory
    # When something goes wrong, you can clear all the Poptools popups
    :PoptoolsKill
    # The displayed colors depends on the value of :h 'background'
    :PoptoolsColorscheme
    :PoptoolsGrepInBuffer # Find pattern in the current buffer
    :PoptoolsGrep # External grep. Grep command is displayed.
     # Vimgrep, show results in the quickfix-list instead of a popup.
    :PoptoolsVimgrep
    :PoptoolsLastSearch # Show the last search results
    :PoptoolsIndex # Create your own dashboard, see :h PoptoolsIndex
<

                                                            *:PoptoolsIndex*
:PoptoolsIndex [{args}]  Open a popup with what is specified in {args}.
                         The type of {args} can be list<string>,
                         list<list<string>> or dict<string>.
                         If no argument is passed, then |g:poptools_index|
                         is considered.

                         Note: This feature is the same as |:MDEIndex| in
                         vim-markdown-extras plugin.

                         Example:
		    >
                            :PoptoolsIndex  # Uses g:poptools_index
                            :PoptoolsIndex [
                                  'local/path',
                                  'some%20url',
                                  'function("some_Funcref")'
                                  ]
                            :PoptoolsIndex {
                                  foo: 'local/path',
                                  bar: 'some%20url', '
                                  baz: function("some_Funcref")'
                                  }
                            :PoptoolsIndex [
                                  ['foo', 'local/path'],
                                  ['bar', 'some%20url'],
                                  ['baz', 'function("some_Funcref")']
                                  ]
<
                          Or it can be used in a script, like for example:
		    >
                            def Foo()
                              const my_index = {
                                foo: '/Users/ubaldot/home/Documents/foo.vim',
                                bar: 'https://example.com',
                                banana: 'function("g:Foo")'
                              }
                            execute $"PoptoolsIndex {my_index}"
                            enddef

                            command! MyIndex Foo()
<
                         The string used in the various cases can be a
                         local path, a valid URL or a function reference.
                         In the latter case, the referenced function must be
                         global and shall take no arguments.

GREP AND VIMGREP                          *poptools-grep*  *poptools-vimgrep*

`PopupToolsVimGrep` uses |vimgrep| whereas `PopupToolsGrep` uses |grep|.
However, the user interface is the same.
The results appear both in the |quickfix-list| and in the popup window.

By default, |grepprg| is set,as it follows:

>
  # Windows
  'powershell -NoProfile -ExecutionPolicy Bypass -Command '
    .. '"& { findstr /C:''' .. what .. ''' /N /S '''
    .. fnamemodify($'{search_dir}\{items}', ':p') .. ''' }"'

  # *nix
  &grepprg = 'grep -nrH --include="{items}" "{what}" {search_dir}'
<

where the values of `{what}`,`{files}` and `{search_dir}` are replaced by
user input values.

You can configure your own |grepprg| command through the keys
`grep_cmd_win` and `grep_cmd_nix` of the |g:poptools_config| dictionary and
you can use the placeholders `{search_dir}, {items}` and `{what}`. See below
for more info.

The grep command sent to the shell can be retrieved through |:messages|. See
below for more info.

TIP: Once you have performed a search, all the results can be accessed at any
time through `:PopupToolsLastSearch` without the need of performing a new
search.

CONFIGURATION                                         *poptools-configuration*

					                                            	*g:poptools_index*
g:poptools_index    list<string>, list<list<string>> or dict<string>.
                    If list<string>, contain the path of indices files.
                    If list<string<string>> the first element of each
                    item of the list is the alias, whereas the second
                    is the link.
                    If dict<string>, the values are the actual links
                    whereas the keys are aliases. In the popup menu only
                    the alias are displayed.
                    Default: empty

                                                        *g:poptools_config*
The plug configuration is done through `g:poptools_config` dictionary.
Be sure to create the empty dictionary `g:poptools_config = {}` before
filling it with he various keys.

      Available keys:
        "preview_file"    Set to `true` if you want a preview window when
                          searching for files.
                          Default: `false`.
"preview_file_in_path"    Set to `true` if you want a preview window when
                          searching for files in path.
                          Default: `false`.
"preview_recent_files"    Set to `true` if you want a preview window when
                          searching for recently opened files.
                          Default: `false`.
     "preview_buffers"    Set to `true` if you want a preview window when
                          searching for buffers.
                          Default: `false`.
       "preview_grep"     Set to `true` if you want a preview window when
                          using poptools grep functions.
                          Default: `false`.
    "preview_vimgrep"     Set to `true` if you want a preview window when
                          using poptools vimgrep functions.
                          Default: `false`.
       "fuzzy_search"     Set to `true` if you want a fuzzy filtering of the
                          results, or to `false` if you want to filter based
                          on exact match. Default: `true`.
       "preview_syntax"   Set to `true` if you want syntax highlighting in the
                          preview window. Note that syntax highlighting may
                          slow down the user-experience. Default: `true`.
      "grep_inc_search"   Set to `false` if you don't want to incrementally
                          search in the current buffer when using `grep`
                          and `vimgrep`. Default: `true`.
       "grep_cmd_win"     Value of |grepprg| for Windows.
                          Default:
      >
              'powershell -NoProfile -ExecutionPolicy Bypass -Command '
                .. '"& { findstr /C:''' .. what .. ''' /N /S '''
                .. fnamemodify($'{search_dir}\{items}', ':p') .. ''' }"'
<

        "grep_cmd_nix"     Value of |grepprg| for *nix systems.
                          Default:
      >
               grep -nrH --include="{items}" "{what}" {search_dir}
<
If you define your own |grepprg|, then the elements in the quickfix shall
contain the buffer number, the line number and the text. You can verify it by
running `:echo getqflist()` . The returned dictionaries must have the keys
`bufnr`, `lnum` and `text`. If that is not the case, then you need to set
|grepformat| adequately. See |grepformat| for more info.
